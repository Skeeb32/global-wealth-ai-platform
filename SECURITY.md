# Security and data handling

This is a public planning starter, not a production system. No production access or credentials are needed.

Do not post exploitable vulnerability details, secrets, investor data, internal documents, or production logs in public issues. If GitHub private vulnerability reporting is enabled, use the repository Security tab to report privately. If it is unavailable, establish a private channel with the maintainer before sharing sensitive details.

Before live deployment, define the threat model, identity provider, authorization boundaries, encryption, secrets storage, retention, incident escalation, and approved model/data processing policies. Test authorization before retrieval and before returning metric values. Log sanitized evidence with appropriate access controls.
